# Design: gh#21 — Remove dead Python 3.10 exceptiongroup compatibility shim

Date: 2026-10-13
Stage: design
Branch: `pipeline/gh-21`
Issue: https://github.com/puckdoug/zpdatafetch/issues/21
Spec: `docs/planning/20261013-gh21-spec.md`

## Approach

Dead-code removal with no intended behavior change. Tests are
characterization/regression guards: they pin observable behavior before the
refactor and must stay green after it. The only new tests lock the
`_fetch_parallel` error propagation that the simplified `except` handler is
responsible for.

Known constraint (from the spec's Assumptions): this branch still declares
`requires-python = ">=3.10"`, tox `py310`, and CI `3.10` matrices. After the
change `zpdatafetch.zpcyclistfetch` imports `BaseExceptionGroup` from
`builtins` unconditionally, so it is no longer importable on 3.10. That is
intended; the full version-configuration change is a separate, out-of-scope
branch, and this branch's 3.10 CI job is expected to fail at import until it is
rebased (the spec now records this as accepted).

**`[tool.ty.environment] python-version` = `"3.11"`.** The spec's acceptance
criterion 4 requires `just check` to pass. With `python-version = "3.10"`, `ty`
reports `builtins` has no member `BaseExceptionGroup` for the unconditional
import required by criterion 1, and `ty` has no per-file `python-version`
override (only `rules` and `analysis` are overridable per file). The spec's
Non-goals now carry an explicit exception permitting this single
type-checker-only setting to be bumped to 3.11; `requires-python`, the tox
`envlist`, and the CI matrices remain untouched. The pending 3.11 support change
supersedes this value when it lands.

**Handler correction.** The spec's requirement 1 asks the `except` handler to
iterate `eg.exceptions` and surface the first `NetworkError`. The pre-change
guard `hasattr(eg, 'exceptions') and callable(getattr(eg, '__iter__', None))`
was always false (`ExceptionGroup` is not iterable), so a `NetworkError` from a
child task was never surfaced. The spec is reconciled: this is a correction of a
latent bug, with exception messages unchanged (acceptance criterion 3).

## Steps

### Step 1 — Error-propagation characterization tests

File: `test/test_zpdatafetch/test_async_cyclist.py` (modify).

Test-first: add two tests. They characterize the corrected handler's two paths;
one (`other_error_reraised`) already passes pre-change, the other
(`network_error_propagates`) fails pre-change and is the regression guard for
the latent bug fixed in Step 3.

- `test_async_cyclist_network_error_propagates`:
  - Build `AsyncZP(skip_credential_check=True)` via the existing pattern.
  - Monkeypatch the session's `fetch_json` to raise
    `shared.exceptions.NetworkError('Failed to fetch Zwift profile')`.
  - `ZPCyclistFetch().set_session(zp)` then
    `pytest.raises(NetworkError, match='Failed to fetch Zwift ID 123456')`
    around `await cyclist.afetch(123456)`.
  - This proves the task-group handler extracts the first `NetworkError` and
    the per-ID message rewrite still applies.
- `test_async_cyclist_other_error_reraised`:
  - Monkeypatch `fetch_json` to raise a plain `RuntimeError('boom')`.
  - Assert `await cyclist.afetch(123456)` raises `BaseExceptionGroup`
    (no `NetworkError` in the group → handler re-raises the group).

Use `@pytest.mark.anyio` and the existing `test/conftest.py` fake-credential
setup. No live API calls.

**Discovery (found during dev).**
`test_async_cyclist_network_error_propagates` fails pre-change. The guard
`hasattr(eg, 'exceptions') and callable(getattr(eg, '__iter__', None))` is
always False — `BaseExceptionGroup`/`ExceptionGroup` is not iterable
(`__iter__` is absent), so the handler never inspected `eg.exceptions` and
always re-raised the group instead of surfacing the `NetworkError`. This is the
latent bug corrected by the Step 3 handler and required by spec requirement 1 /
acceptance criterion 3. Steps 1 and 3 are committed together to keep the tree
green, and both checklist boxes are ticked in that commit.
`test_async_cyclist_other_error_reraised` passes both pre- and post-change.

### Step 3 — `zpcyclistfetch.py` cleanup

File: `src/zpdatafetch/zpcyclistfetch.py` (modify).

- Remove `import sys` (line 5).
- Replace lines 12-23 (the `if sys.version_info >= (3, 11):` / `else:` block)
  with a single unconditional `from builtins import BaseExceptionGroup`.
- In the `except BaseExceptionGroup as eg:` handler (193-211), delete the
  `hasattr`/`callable` guard and the stale comments; replace with:

  ```python
  except BaseExceptionGroup as eg:
    # Extract the first NetworkError from the exception group
    from shared.exceptions import NetworkError

    for exc in eg.exceptions:
      if isinstance(exc, NetworkError):
        raise exc
    # If no NetworkError found, re-raise the exception group
    raise
  ```

Behavior contract (unchanged): first `NetworkError` in the group is raised;
otherwise the group is re-raised. No change to the `fetch_and_store` handler
or its messages.

Also in this step: set `[tool.ty.environment] python-version = "3.11"` in
`pyproject.toml` so the unconditional `builtins` import type-checks (see the
note above). Without it `just check` fails; no per-file `python-version`
override exists in `ty`.

Verify (spec acceptance 1):
`grep -n "version_info\|exceptiongroup\|^import sys" src/zpdatafetch/zpcyclistfetch.py`
returns no matches.
