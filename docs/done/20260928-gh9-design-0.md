## Design

### Current behavior

`ZwiftRideOns.give_rideon()` (`src/zdatafetch/rideons.py:265`) POSTs with
no body. The Zwift API requires `{"profileId": <caller id>}` with
`Content-Type: application/json`; without it the endpoint returns 415.

### Fix

Two changes inside `give_rideon()` only (signature, CLI, and `fetch()` /
`fetch_multiple()` / `_parse_response()` untouched):

1. **Resolve caller id** before the POST loop body:
   - `GET {BASE_URL}/api/profiles/me` with the same `headers` already
     built after `ZwiftAuth.login()`.
   - Parse with `parse_json_safe(response.text, context='rideons')`,
     then `me_id = int(data['id'])`.
   - On non-200 status, unparseable body, missing/absent `id`, or
     `httpx2` exception: `logger.error(...)` and return `False`. No POST
     is attempted.
2. **Send the payload**: `client.post(url, headers=headers,
   json={'profileId': me_id}, timeout=30.0)`. `httpx2` sets
   `Content-Type: application/json` automatically. Response handling
   (200/201/204 → `True`; 404 and other → logged error, `False`;
   timeout/HTTPError → logged error, `False`) is unchanged.

`rider_id` (the activity owner) stays only in the URL path; the payload
carries the authenticated caller's id — they may differ.

### Test approach

Follow the existing module pattern: replace `httpx2.Client` with
`MockTransport(handler)`, monkeypatch `zdatafetch.rideons.Config` and
`zdatafetch.auth` client (same try/finally restore as `test_profile.py`).
Credentials come from a `MockConfig` class — no keyring involved.

New fixture `give_rideon_handler` in `test/test_zdatafetch/conftest.py`,
a stateful handler recording requests and asserting behavior:

- `POST .../auth/realms/...` → token response (reuse `auth_handler`
  logic via `mock_token_response`).
- `GET /api/profiles/me` → `200` with `{'id': 424242, ...}` (minimal
  body; `id` is what matters).
- `POST /api/profiles/{owner}/activities/{aid}/rideon`:
  - if `request.headers` lacks `content-type: application/json` or the
    body is not `{"profileId": 424242}` → `415` (reproduces the bug).
  - else → `200`.
  - Handler modes via closure flags for failure cases (`me_status`,
    `post_status`, `me_body`).

Assertions capture `request.method`, `request.url`, and
`json.loads(request.content)` for each call so tests verify both the
owner-id URL and the caller-id payload.

## Steps

### Step 1 — Failing tests: happy path + regression

Tests in `test/test_zdatafetch/test_rideons.py` (write first; all fail
against current code):

- `test_give_rideon_sends_payload` (regression): with the fixture
  returning 415 for body-less/mistyped POSTs and 200 for a correct one,
  `give_rideon(550564, 12345678)` returns `True`; the recorded POST URL
  is `/api/profiles/550564/activities/12345678/rideon`; the POST body is
  `{'profileId': 424242}`. Fails now (415 raised → returns `False`).
- `test_give_rideon_resolves_me_before_post`: the mock returns 500 on
  POST unless a prior `GET /api/profiles/me` was recorded; asserts
  request order (`me` then POST) and that `profileId` equals the `me`
  response's `id`.

### Step 2 — Failing tests: error paths

- `test_give_rideon_me_500_returns_false`: `/me` → 500 → returns
  `False`, no POST recorded, error logged (use `caplog`).
- `test_give_rideon_me_missing_id_returns_false`: `/me` → 200 body
  `{'firstName': 'X'}` → returns `False`, no POST recorded.
- `test_give_rideon_me_network_error_returns_false`: `/me` raises
  `httpx2.ConnectError` → returns `False`, no POST.
- `test_give_rideon_post_404_returns_false` and
  `test_give_rideon_post_500_returns_false`: `/me` → 200, POST → 404/500
  → `False`, error logged.
- `test_give_rideon_timeout_returns_false`: POST raises
  `httpx2.TimeoutException` → `False`.

### Step 3 — Implement

In `src/zdatafetch/rideons.py`, `give_rideon()`:

- After building `headers`, open the client once; inside it, first
  `client.get(f'{ZwiftRideOns.BASE_URL}/api/profiles/me', headers=headers, timeout=30.0)`.
  Non-200 → `logger.error(f'Failed to resolve authenticated rider id: HTTP {status}')`,
  return `False`. Parse via `parse_json_safe(..., context='rideons')`;
  `id` missing/not int-able → logged error, `False`.
- Change the POST line to
  `client.post(url, headers=headers, json={'profileId': me_id}, timeout=30.0)`.
- Extend the existing `except httpx2.TimeoutException` /
  `except httpx2.HTTPError` blocks to cover the `me` request too (they
  already wrap the whole `with` block — no structural change needed).
- Update the docstring: note the `/api/profiles/me` lookup and payload.

Keep line length ≤ 80, single quotes, type hints.
