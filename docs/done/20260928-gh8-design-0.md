## Verified API shape (source of truth)

Upstream doc `strukturunion-mmw/zwift-api-documentation`,
`riderProfiles/list_followers.md` (fetched 2026-09-28). Each entry of the
`/api/profiles/{riderId}/followers` response is a **relation object**:

```json
{
  "id": 0,
  "followerId": 33514,
  "followeeId": 33388,
  "status": "IS_FOLLOWING",
  "isFolloweeFavoriteOfFollower": false,
  "followerProfile": { "id": 33514, "...": "full rider profile incl. socialFacts.followersCount" },
  "followeeProfile": null
}
```

- Top-level `id` is the **relation row id** per the upstream doc (doc
  examples show `0`), NOT the rider's ID. The rider's ID lives in the
  nested `followerProfile.id` / `followeeProfile.id`.
  LIVE CONFIRMATION (2026-09-28, rider 6560916, 684 followers): the
  top-level `id` is `0` for EVERY record — a constant, not even a per-row
  id. `followerId` == `followerProfile.id` holds. So `follower_ids()` /
  `followee_ids()` return lists of constant 0 — the gh#11-class bug is
  confirmed, not merely suspected (still out of scope here).
- The followees endpoint (`list_followees.md`) uses the mirrored shape
  (`followeeProfile` populated).
- Consequence recorded but OUT OF SCOPE here: `follower_ids()` /
  `followee_ids()` extract the top-level relation `id`, so they very likely
  return relation row IDs, not rider IDs — the same bug gh#11 fixed for
  RideOns. Spec for gh#8 limits scope to pagination; do not touch these
  helpers. Flag it to Doug in the final issue comment as a candidate
  follow-up issue.
- Pagination is shape-agnostic (the helper just concatenates list pages), so
  this shape uncertainty does not affect the fix itself; it only matters for
  unit-test fixtures, which must mirror the documented shape (spec criterion
  3).

## Design decisions

1. **Helper signature: `_fetch_paginated(client, url, headers, rider_id,
   kind, mode)`.** The spec sketched `(client, url, headers, context)`.
   Splitting `context` into `rider_id` + `kind` + `mode` lets the helper
   reproduce every existing error/warning message exactly:
   - 404, raise mode → `NetworkError('Rider {rider_id} not found')`
     (current `fetch()` followers and followees message)
   - non-200, raise mode → `NetworkError('Failed to fetch {kind} for rider
     {rider_id}: HTTP {code} - {text}')` (current `fetch()` followers
     message)
   - non-200, partial mode → warning `'Failed to fetch {kind} for rider
     {rider_id}: HTTP {code}'` (current `fetch_multiple()` warning text)
   `mode` is `Literal['raise', 'partial']`.
2. **Helper is a module-level private function**, not a method: it needs no
   instance or class state (called from both the instance method `fetch()`
   and the classmethod `fetch_multiple()`), and is directly unit-testable.
   The spec's "private helper (e.g. ...)" allows this.
3. **Modes:** `fetch()` followers → `'raise'`; `fetch_multiple()` followers
   → `'raise'` too — its `NetworkError` is caught by the existing per-rider
   `except Exception` → warning logged, rider skipped. That reproduces the
   current skip semantics (spec item 6) without a third mode; the only
   observable difference is the log line level (error instead of warning)
   and text, while the outcome (rider absent from results) is identical.
   Followees (both paths) → `'partial'`.
4. **Followees 404 changes from raise to warn.** Current code raises
   `NetworkError('Rider not found')` on a followees 404 in `fetch()`. Spec
   item 6 states followees failures log a warning and keep collected pages
   in BOTH paths, with no 404 carve-out ("empty list if the first page
   fails"). A rider whose followers page returns 200 but whose followees
   page 404s is an API anomaly, not a missing rider. Decision: all non-200
   followees pages → warning + partial. Documented here so the quality
   stage can review it against the spec text.
5. **Stop condition is one check:** `len(page_records) < PAGE_SIZE` after
   extending. An empty page (0 < 200) and a short final page (50 < 200) are
   the same branch, so both spec-mandated stop conditions hold. A page
   returning MORE than `PAGE_SIZE` (server ignoring `limit`) keeps
   paginating; the `MAX_PAGES` cap guarantees termination.
6. **Loop guard via `for … else`:** `for page in range(MAX_PAGES)` with a
   `break` on every stop condition; the `else` clause (loop exhausted
   without break) logs the cap warning and falls through to returning the
   partial data. If the last allowed page is short, the in-loop break wins
   and no warning fires.
7. **Constants `PAGE_SIZE = 200`, `MAX_PAGES = 500` are module-level names
   read at call time** inside the helper (not baked into defaults), so the
   loop-guard unit test can monkeypatch them small (e.g. 2/3) instead of
   building 100k records.
8. **Page payloads are parsed in the helper** with `parse_json_safe` and
   merged into one `list[dict]`; callers store them back as
   `raw_data[kind] = json.dumps(records)`. `_parse_response()` stays the
   single parse point and is untouched, so `_fetched` / `_raw` / attribute
   shape is unchanged (spec item 4). A 200 page whose body is not a list
   (parse failure, `{}`, empty string) logs a warning and stops pagination,
   returning pages collected so far — this matches today's behavior for
   malformed payloads (empty lists, no raise).
9. **`timeout=30.0` and headers pass through unchanged**; query parameters
   go via `params={'start': start, 'limit': PAGE_SIZE}` — the same pattern
   `ZwiftActivity.fetch()` already uses in this package.
10. **No public signature changes.** `fetch()` / `fetch_multiple()` /
    helpers / CLI all keep their current signatures; CLI and README output
    format unchanged.
11. **Unit tests mock at the `httpx2.Client` layer** with
    `httpx2.MockTransport`, following `test/test_zdatafetch/test_profile.py`
    (`test_fetch_single_profile`): patch `zdatafetch.auth.httpx2.Client` and
    `zdatafetch.followers.httpx2.Client` (same module object), monkeypatch
    `Config`, restore the client in `finally`. `ZwiftAuth`'s token POST is
    answered by the same handler (token JSON), so no keyring or real auth
    happens in unit tests (root conftest already fakes keyrings).
12. **TDD order mirrors gh#11:** live shape test (green on unfixed code —
    gate), live pagination test (red), unit pagination tests (red), then
    the fix turns them green, then docs.

class PageSource:
  """In-memory paginated endpoints served through MockTransport.

  Pages map (rider_id, endpoint, start) to a list of records, an HTTP
  status int to force a failure, or a str to serve as raw body. Every
  request is recorded as (rider_id, endpoint, start, limit).
  """

  def __init__(self):
    self.pages = {}
    self.requests = []

  def add(self, rider_id, endpoint, start, page):
    self.pages[(rider_id, endpoint, start)] = page

  def handler(self, request):
    if 'access/codes' in str(request.url):
      return httpx2.Response(200, text=json.dumps(TOKEN_RESPONSE))
    parts = str(request.url).split('?')[0].split('/')
    rider_id = int(parts[-2])
    endpoint = parts[-1]
    start = int(request.url.params.get('start', 0))
    limit = int(request.url.params.get('limit', 0))
    self.requests.append((rider_id, endpoint, start, limit))
    page = self.pages.get((rider_id, endpoint, start))
    if page is None:
      return httpx2.Response(404, text='Not found')
    if isinstance(page, str):
      return httpx2.Response(200, text=page)
    if isinstance(page, int):
      return httpx2.Response(page, text='error')
    return httpx2.Response(200, text=json.dumps(page))


def patch_fetch(source, monkeypatch):
  """Patch auth, config, and HTTP client to serve source's pages."""
  import zdatafetch.auth

  original_client = httpx2.Client

  def mock_client(*args, **kwargs):
    return original_client(transport=httpx2.MockTransport(source.handler))

  zdatafetch.auth.httpx2.Client = mock_client
  followers_mod.httpx2.Client = mock_client

  class MockConfig:
    username = 'test@example.com'
    password = 'testpassword'

    def load(self):
      pass

  monkeypatch.setattr(followers_mod, 'Config', MockConfig)
  return original_client


def restore_clients(original_client):
  """Restore the real httpx2.Client after a test."""
  import zdatafetch.auth

  zdatafetch.auth.httpx2.Client = original_client
  followers_mod.httpx2.Client = original_client


def expose_warnings(caplog, monkeypatch):
  """Route zdatafetch log records into caplog for warning assertions."""
  caplog.set_level(logging.WARNING, logger='zdatafetch.followers')
  monkeypatch.setattr(logging.getLogger('zdatafetch'), 'propagate', True)
  monkeypatch.setattr(
    logging.getLogger('zdatafetch.followers'), 'propagate', True,
  )

### Step 3 — implementation (file: modify `src/zdatafetch/followers.py`)

1. Change the typing import to `from typing import Any, Literal`.
2. Add after `logger = get_logger(__name__)`:

```python
PAGE_SIZE = 200
MAX_PAGES = 500


def _fetch_paginated(
  client: httpx2.Client,
  url: str,
  headers: dict[str, str],
  rider_id: int,
  kind: str,
  mode: Literal['raise', 'partial'],
) -> list[dict[str, Any]]:
  """Fetch all pages of a followers/followees endpoint.

  Zwift caps these endpoints at ``PAGE_SIZE`` entries per request. Each
  request sends ``start``/``limit`` query parameters; pagination stops
  when a page is empty or shorter than ``PAGE_SIZE``.

  Args:
      client: httpx2 client to request with
      url: Endpoint URL (without start/limit parameters)
      headers: Request headers
      rider_id: Zwift rider ID (for logs and error messages)
      kind: Endpoint label, 'followers' or 'followees'
      mode: 'raise' raises NetworkError on a failed page; 'partial'
          logs a warning and returns the pages collected so far

  Returns:
      Records merged across all fetched pages

  Raises:
      NetworkError: In 'raise' mode, if a page does not return 200
  """
  records: list[dict[str, Any]] = []
  for page in range(MAX_PAGES):
    start = page * PAGE_SIZE
    response = client.get(
      url,
      headers=headers,
      params={'start': start, 'limit': PAGE_SIZE},
      timeout=30.0,
    )

    if response.status_code != 200:
      if mode == 'raise':
        if response.status_code == 404:
          raise NetworkError(f'Rider {rider_id} not found')
        raise NetworkError(
          f'Failed to fetch {kind} for rider {rider_id}: '
          f'HTTP {response.status_code} - {response.text}',
        )
      logger.warning(
        f'Failed to fetch {kind} for rider {rider_id}: '
        f'HTTP {response.status_code}',
      )
      break

    page_records = parse_json_safe(response.text, context=kind)
    if not isinstance(page_records, list):
      logger.warning(
        f'Unexpected payload for {kind} of rider {rider_id} '
        f'at start={start}: expected list, '
        f'got {type(page_records).__name__}',
      )
      break

    records.extend(page_records)
    logger.debug(
      f'Fetched {kind} page for rider {rider_id} '
      f'(start={start}): {len(page_records)} records',
    )

    if len(page_records) < PAGE_SIZE:
      break
  else:
    logger.warning(
      f'Pagination cap of {MAX_PAGES} pages reached for {kind} of '
      f'rider {rider_id}: returning partial data '
      f'({len(records)} records)',
    )

  return records
```
