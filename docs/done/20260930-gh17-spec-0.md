# GH #17 spec — Add vELO2 skill and category data to ZRRider

Date: 2026-09-30
Issue: https://github.com/puckdoug/zpdatafetch/issues/17

## Problem

The Zwiftracing rider endpoint returns a `velo` (vELO2) block that includes
`race`, `factors.*`, `skill.*`, and `category.{number,name}`. `ZRRider`
already captures `velo.race` and `velo.factors.*` (added in v2.1.0), but it
silently discards `velo.skill.*` and `velo.category.*`.

Because `velo` is listed in `known_fields` in `ZRRider.from_dict()`, the
dropped sub-fields are not even preserved in `_extra` or `_excluded` — the
data is unrecoverable from the object. The `seed` block is already captured
in full, so this issue is only about the missing `velo` sub-fields.

Evidence — the issue sample:

```json
"velo": {
  "race": 430.1083267869261,
  "factors": {
    "endurance": 410,
    "pursuit": 384,
    "sprint": 545.3206484167583,
    "punch": 484.82,
    "climb": 374,
    "timeTrial": 507
  },
  "skill": {
    "endurance": 0,
    "pursuit": 0,
    "sprint": 0.3206484167583312,
    "punch": 0,
    "climb": 0,
    "timeTrial": 0
  },
  "category": { "number": 8, "name": "Silver" }
}
```

Current behavior for that sample: `asdict()` returns only `velo_race`,
`velo_time_trial`, `velo_endurance`, `velo_pursuit`, `velo_sprint`,
`velo_punch`, `velo_climb`, `velo_time_trial_factor`. The `skill` and
`category` values are absent from the object, `extras()`, and `excluded()`.

## Required behavior

1. `ZRRider` exposes every value in the `velo.skill` and `velo.category`
   sub-objects. Use flat fields consistent with the existing `velo_*`
   convention:

   | Field                  | Type    | Default | Source                      |
   | ---------------------- | ------- | ------- | --------------------------- |
   | `velo_skill_endurance` | `float` | `0.0`   | `velo.skill.endurance`      |
   | `velo_skill_pursuit`   | `float` | `0.0`   | `velo.skill.pursuit`        |
   | `velo_skill_sprint`    | `float` | `0.0`   | `velo.skill.sprint`         |
   | `velo_skill_punch`     | `float` | `0.0`   | `velo.skill.punch`          |
   | `velo_skill_climb`     | `float` | `0.0`   | `velo.skill.climb`          |
   | `velo_skill_time_trial`| `float` | `0.0`   | `velo.skill.timeTrial`      |
   | `velo_category_number` | `int`   | `0`     | `velo.category.number`      |
   | `velo_category_name`   | `str`   | `''`    | `velo.category.name`        |

2. `ZRRider.from_dict()` extracts each field with
   `extract_nested_value()` plus the matching `safe_float()` /
   `safe_int()` / `safe_str()` helper, following the existing pattern.

3. Missing or malformed values fall back to the defaults in the table (no
   exception), matching the existing optional-field behavior.

4. The new fields appear in `asdict()` and in the default dataclass
   `repr`. `_extra` / `_excluded` behavior is unchanged; `velo` stays in
   `known_fields` (the sub-object is now typed, so it must not leak into
   extras).

5. All existing `ZRRider` fields keep their current values for existing
   fixtures — no regression to seed, factor, handicap, phenotype, or race
   stat extraction.

6. The `ZRRider` class docstring is updated to document the new
   attributes.

## Non-goals

- No change to `seed` extraction (already complete).
- No `race.current.mixed.number` / category-number extraction; only the
  `velo.category` values requested in the issue.
- No nested sub-dataclass for `velo` unless the design stage prefers it;
  flat `velo_*` naming is the established convention.
- No change to fetch endpoints, CLI flags, `--raw` output, or JSON output
  format beyond the added fields.
- No new dependency.
- Not fixing the `zwift_id == 0` reconstruction path in
  `zrriderfetch.py` (logged below).

## Tests

Unit tests in `test/test_zrdatafetch/test_zrrider.py`, driven by a fixture
that matches the issue sample (add `skill` / `category` to
`test/fixtures/zr_rider_550564.json` or add a new fixture):

1. Every new field is extracted with the correct value from the issue
   sample (`velo_skill_sprint == 0.3206484167583312`,
   `velo_category_number == 8`, `velo_category_name == 'Silver'`, etc.).
2. Omitted `velo.skill` / `velo.category` yields the documented defaults.
3. `asdict()` includes all eight new fields.
4. Existing `velo.*` and `seed.*` tests continue to pass unchanged.

## Acceptance criteria

- [ ] `ZRRider` exposes the eight new fields listed above.

- [ ] No existing `test_zrrider.py` assertion changes.

None. The issue provides the exact desired `velo` shape and the only

## Logged follow-up (not part of this issue)

`src/zrdatafetch/zrriderfetch.py` rebuilds a fresh `ZRRider` when the API
response omits `riderId`/`zwiftId` (`rider.zwift_id == 0`), copying only
`zwift_id`, `name`, `gender`, `current_rating`, `current_rank`,
`max30_*`, `max90_*`, `zrcs`, and the private dicts. That drops
handicaps, phenotype, seed, velo, and race stats. Proposed fix: replace
the manual rebuild in `_afetch_internal()` and `_fetch_sync()` with
`dataclasses.replace(rider, zwift_id=zwift_id)`. Add a regression test
with a response that has `name`/`race` but no `riderId`. Track
separately from GH #17.
