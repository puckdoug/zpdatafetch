## Verified production data (2026-09-28)

Read-only live probe (`GET` rideon lists for riders 550564 and 486314, real
keyring creds from domain `zdatafetch`). Findings, checked across 126 records
on 2 riders:

- Every record has top-level `id` (int) = **rideon record ID** (e.g.
  `5597718940`), never equal to a rider ID. This is what the current code
  wrongly returns.
- Every record has top-level `profileId` (int) == nested `profile.id` (int).
  Equal in 126/126 records, never `None`.
- Record field set (verified; sample with fake values):

The spec's assumed shape (`profile.id` nesting) is confirmed. The upstream doc
(`rideOns/list_rideOns.md`) documents the response as an empty object, so the
live API is the only source of truth here. The followers endpoint's doc shows
the same relation-object pattern (`id` = relation row id + nested profile),
which is why `follower_ids()`/`followee_ids()` are suspected same-bug — still
out of scope per the spec.

## Design decisions

1. **Extract from nested `profile.id` only.** Top-level `profileId` exists and
   equals `profile.id` on production data, but no fallback to it: the spec
   mandates `profile.id`, and a fallback would mask shape drift. If `profile`
   is unusable the record is skipped, full stop.
2. **Skip rules keep the return `list[int]`.** Skip a record when: `profile`
   is missing / `None` / not a dict; or `profile.id` is missing / not an int.
   Exclude `bool` explicitly (`isinstance(True, int)` is `True`). Never emit
   `None` or raise on malformed entries.
3. **`has_rideon_from()` is untouched.** It delegates to `rideon_ids()` and
   becomes correct automatically.
4. **Everything else untouched.** `fetch()`, `fetch_multiple()`,
   `give_rideon()`, `_parse_response()` unchanged; `self.rideons` and
   `self._fetched` keep the full parsed records.
5. **Unit fixtures are inline, real-shaped, fake-valued.** The real payload
   contains other riders' names and image URLs (PII) — do not commit it. A
   `make_rideon()` helper in the test file builds records with the exact
   verified field set and fake names/URLs.
6. **Live tests pick an activity at runtime.** They fetch recent activities
   for a fixed rider, fetch RideOns for each until one is non-empty, and
   `pytest.skip` if none found. No hardcoded activity IDs that age out.
7. **Live credential plumbing already works.** `zdatafetch.Config` uses
   keyring domain `'zdatafetch'`; the root conftest fakes only the
   `zpdatafetch` and `zrdatafetch` domains, and
   `test/live/conftest.py::use_real_credentials` restores the real system
   keyring. No new credential handling is needed.
8. **TDD order.** Live shape test (must pass on unfixed code — it only reads
   raw records) gates the re-spec question; live behavior test and unit
   regression tests are red first, then the fix turns them green.

```python
"""Live tests for ZwiftRideOns against the real Zwift API (gh#11)."""

import pytest

from zdatafetch.activity import ZwiftActivity
from zdatafetch.rideons import ZwiftRideOns


def _rideons_with_data(rider_id):
  """Fetch RideOns for recent activities until one is non-empty."""
  acts = ZwiftActivity()
  acts.fetch(rider_id, start=0, limit=20)
  for activity_id in acts.activity_ids()[:5]:
    rideons = ZwiftRideOns()
    rideons.fetch(rider_id, activity_id)
    if rideons.rideon_count() > 0:
      return rideons
  pytest.skip('no RideOns found in recent activities')


@pytest.mark.live
def test_live_rideons_record_shape(zdata_rider_id):
  """Production records must nest the rider ID at profile.id (gh#11)."""
  rideons = _rideons_with_data(zdata_rider_id)
  for record in rideons.rideons:
    profile = record.get('profile')
    assert isinstance(profile, dict)
    assert isinstance(profile.get('id'), int)
    assert profile['id'] == record['profileId']
    assert isinstance(record['id'], int)


@pytest.mark.live
def test_live_rideon_ids_are_rider_ids(zdata_rider_id):
  """rideon_ids() must return rider IDs that has_rideon_from() matches."""
  rideons = _rideons_with_data(zdata_rider_id)
  ids = rideons.rideon_ids()
  assert len(ids) > 0
  assert all(isinstance(i, int) for i in ids)
  for record in rideons.rideons:
    profile = record.get('profile')
    if isinstance(profile, dict) and isinstance(profile.get('id'), int):
      assert rideons.has_rideon_from(profile['id']) is True
  assert rideons.has_rideon_from(0) is False
```

### Step 3 — the fix (file: modify `src/zdatafetch/rideons.py`, `rideon_ids()` only)

```python
def rideon_ids(self) -> list[int]:
  """Return list of rider IDs who gave RideOns.

  Each rideon record carries the rideon's own ``id`` and the giving
  rider's ID in the nested ``profile.id`` field (shape verified against
  the live API). Records without a usable rider ID are skipped.

  Returns:
      List of rider IDs who gave RideOns to this activity
  """
  ids: list[int] = []
  for record in self.rideons:
    profile = record.get('profile')
    if not isinstance(profile, dict):
      continue
    rider_id = profile.get('id')
    if isinstance(rider_id, int) and not isinstance(rider_id, bool):
      ids.append(rider_id)
  return ids
```

→ green.
