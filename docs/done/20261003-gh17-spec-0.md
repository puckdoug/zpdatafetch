# GH #17 spec (extension) — Add vELO2 max30/max90 to ZRRider

Date: 2026-10-03
Issue: https://github.com/puckdoug/zpdatafetch/issues/17
Branch: `pipeline/gh-17`

This spec extends the already-implemented vELO2 `skill` / `category` work
(see `docs/planning/20260930-gh17-spec.md`). It covers only the new
`max30` / `max90` values requested in the issue comment.

## Problem

The Zwiftracing rider endpoint now returns additional `velo` fields:
`max30`, `max90`, `max30Category.{number,name}`, and
`max90Category.{number,name}`. `ZRRider` already captures `velo.race`,
`velo.factors.*`, `velo.skill.*`, and `velo.category.*`, but it silently
discards these new sub-fields.

Because `velo` is listed in `known_fields` in `ZRRider.from_dict()`, the
dropped values are not preserved in `_extra` or `_excluded` — the data is
unrecoverable from the object.

Evidence — the issue comment's sample:

```json
"velo": {
    "race": 430.0373767869261,
    "factors": {
      "endurance": 410,
      "pursuit": 384,
      "sprint": 545.3206484167583,
      "punch": 484.49,
      "climb": 374,
      "timeTrial": 507
    },
    "skill": {
      "endurance": 0,
      "pursuit": 0,
      "sprint": 0.3206484167583312,
      "punch": 0,
      "climb": 0,
      "timeTrial": 0
    },
    "category": {
      "number": 8,
      "name": "Silver"
    },
    "max30": 434.86035000000004,
    "max90": 453.5100245027948,
    "max30Category": {
      "number": 8,
      "name": "Silver"
    },
    "max90Category": {
      "number": 8,
      "name": "Silver"
    }
  }
```

## Required behavior

1. `ZRRider` exposes every new value as flat fields, following the existing
   `velo_*` convention:

   | Field                        | Type    | Default | Source                        |
   | ---------------------------- | ------- | ------- | ----------------------------- |
   | `velo_max30`                 | `float` | `0.0`   | `velo.max30`                  |
   | `velo_max90`                 | `float` | `0.0`   | `velo.max90`                  |
   | `velo_max30_category_number` | `int`   | `0`     | `velo.max30Category.number`   |
   | `velo_max30_category_name`   | `str`   | `''`    | `velo.max30Category.name`     |
   | `velo_max90_category_number` | `int`   | `0`     | `velo.max90Category.number`   |
   | `velo_max90_category_name`   | `str`   | `''`    | `velo.max90Category.name`     |

2. `ZRRider.from_dict()` extracts each field with
   `extract_nested_value()` plus the matching `safe_float()` /
   `safe_int()` / `safe_str()` helper, following the existing pattern.

3. Missing or malformed values fall back to the defaults in the table (no
   exception), matching existing optional-field behavior.

4. The new fields appear in `asdict()` and in the default dataclass `repr`.
   `_extra` / `_excluded` behavior is unchanged; `velo` stays in
   `known_fields`.

5. No existing `ZRRider` field changes value for the existing fixture.

6. The `ZRRider` class docstring is updated to document the new attributes.

## Non-goals

- No change to the existing `velo.race`, `velo.factors.*`, `velo.skill.*`,
  or `velo.category.*` behavior.
- No change to `seed`, handicaps, phenotype, race stats, fetch endpoints,
  CLI flags, `--raw`, or JSON output beyond the added fields.
- No nested sub-dataclass for `velo`; flat `velo_*` naming is the
  established convention.
- No new dependency.
- Not fixing the `zwift_id == 0` reconstruction path in
  `zrriderfetch.py` (logged follow-up from the prior spec).

## Tests

Unit tests in `test/test_zrdatafetch/test_zrrider.py`, driven by the
existing fixture `test/fixtures/zr_rider_550564.json`:

1. Add the four new keys (`max30`, `max90`, `max30Category`,
   `max90Category`) to the fixture's `velo` object using the exact values
   from the issue comment. Keep the fixture's existing `race` / `factors` /
   `skill` / `category` values so no existing assertion changes.
2. Every new field is extracted with the correct value
   (`velo_max30 == 434.86035000000004`,
   `velo_max90 == 453.5100245027948`,
   `velo_max30_category_number == 8`,
   `velo_max30_category_name == 'Silver'`,
   `velo_max90_category_number == 8`,
   `velo_max90_category_name == 'Silver'`).
3. Omitted `velo.max30` / `velo.max90` / `max30Category` /
   `max90Category` yields the documented defaults.
4. Malformed values fall back to defaults without raising.
5. `asdict()` and `repr` include all six new fields.
6. Existing `velo.*`, `skill.*`, `category.*`, and `seed.*` tests continue
   to pass unchanged.
