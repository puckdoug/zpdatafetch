# GH #9 spec — `give_rideon()` sends HTTP 415 (missing payload)

Date: 2026-09-28
Issue: https://github.com/puckdoug/zpdatafetch/issues/9
Reporter: andrzejbluszcz

## Problem

`ZwiftRideOns.give_rideon(rider_id, activity_id)` always fails with
`HTTP 415 - Unsupported Media Type`.

Root cause: `src/zdatafetch/rideons.py:265` posts with no body:

```python
response = client.post(url, headers=headers, timeout=30.0)
```

The Zwift API requires a JSON payload for this endpoint
(strukturunion-mmw/zwift-api-documentation, `rideOns/give_rideOn.md`):

- URL: `POST /api/profiles/{riderId}/activities/{activityId}/rideon`
  — `riderId` = the **activity owner**.
- Required payload: `{"profileId": <integer id of the authenticated user
  giving the RideOn>}` — i.e. the **caller's own** Zwift ID.

The reporter confirmed the fix works with:

```python
payload = {"profileId": ZwiftId}
response = client.post(url, headers=headers, json=payload, timeout=30.0)
```

## Required behavior

1. `give_rideon()` resolves the authenticated user's Zwift ID via
   `GET {BASE_URL}/api/profiles/me` (documented endpoint; response `id`
   field). This avoids JWT-decoding the `id_token` and requires no new
   dependency. `give_rideon()` already performs a fresh login per call,
   so one extra request is acceptable.
2. The POST then sends `json={"profileId": <int>}`. `httpx2` sets
   `Content-Type: application/json` automatically when `json=` is used,
   which is what the endpoint needs (415 today = missing/incorrect
   content type + body).
3. Public signature is unchanged: `give_rideon(rider_id: int, activity_id: int) -> bool`.
   Callers (CLI `zdata rideon --give`) need no changes.
4. Existing response handling is unchanged: 200/201/204 → `True`,
   404 and other non-success → logged error, `False`. Network/timeout
   exceptions → logged error, `False`.
5. If `GET /api/profiles/me` fails or its response has no `id`, log the
   error and return `False` (do not raise; matches the method's
   existing error contract).
6. `me` response parsing: `parse_json_safe(..., context='rideons')`,
   extract `int(data['id'])`.

## Non-goals

- No change to `fetch()` / `fetch_multiple()` / `_parse_response()`.
- No caching of the `/api/profiles/me` result across calls.
- No change to the `give_rideon()` signature or CLI surface.
- No JWT/`id_token` decoding.
- No retry/backoff changes (the shared HTTP layer is out of scope).

## Tests

Unit tests in `test/test_zdatafetch/test_rideons.py`, using the
existing respx/mock handler pattern from `conftest.py`:

1. **Regression test (exact production scenario)**: mock server returns
   415 when the POST has no JSON body or wrong `Content-Type`, 200 when
   `{"profileId": <id>}` is present. `give_rideon()` must return `True`
   and the request must carry the correct payload. Mirror of the
   reporter's failure: URL path uses activity owner id, payload uses the
   authenticated user's id — both asserted.
2. `GET /api/profiles/me` is called before the POST and its `id` is used
   as `profileId`.
3. 404 on POST → `False`; 500 on POST → `False` (error logged).
4. `/api/profiles/me` failure (500, or response without `id`) → `False`
   and no POST attempted.
5. Existing rideon fetch tests keep passing.
